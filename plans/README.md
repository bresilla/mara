## Findings considered and rejected (do not re-audit)

- **`ureq` + `ehttp` duplication in `mara_map`** — ehttp wraps ureq on
  native; consolidation buys little. Revisit only if the map module grows a
  real network layer.
- **Bevy CPU-readback triple copy** (`modules/bevy/egui_view.rs:390-417`) —
  fallback-only path (native runner supplies `render_state` and takes the
  zero-copy GPU route). Fix only if a real host exercises the fallback.
- **Ribbon/shelf per-frame `Vec` churn** (`ribbon/slot_paint.rs:127-177`) —
  LOW confidence without a profile; profile the shell render before touching
  scratch-buffer reuse.
- **Native chrome press consumed without informing egui**
  (`mara/src/window.rs:477-481`) — minor stuck-hover glitch, MED confidence,
  platform-dependent; bundle into a future window-chrome pass rather than
  its own plan.
- **One-frame ShellBar id collision on fallback→app-bar transition**
  (`enforce.rs:217-245`) — transient, needs a live repro to confirm; the
  enforce module is uncommitted and still moving. Revisit after it settles.
- **Multi-context screen-metrics thrash as its own plan** — folded into
  plan 013 Stage C.
- **"Four divergent docking copies" hypothesis** — investigated and
  disproved: shelf/pane genuinely share `container::Tab`/`ContainerSpec`;
  the real debt is the `normal` god object (plan 014).
- **`egui 0.34` / `wgpu 29` / `bevy 0.19` version-lag migration** — could
  not verify lag offline; lockfile is internally consistent with no
  duplicate majors. Re-check at next release prep.
- **`make docs` target auto-commits** (`git add --all && git commit`) inside
  a build target — surprising but deliberate-looking; flag to the maintainer
  rather than plan around it.
